ARMarketer: Teammate Visual Guide

Welcome to the ARMarketer project! This guide will get you oriented quickly.

1. Project Overview

ARMarketer is a Web AR/VR/3D marketing platform designed to replace Zapworks-dependent delivery. It allows users to upload 3D models, associate them with image targets, and view them in a web-based AR experience.

2. Current Status & Gates

We are currently in Phase 1 (W5 in progress).

  • Gate 1 (PASSED): MindAR 1.2.5 stable on iOS Safari & Android Chrome.
  • Gate 2 (PASS-WITH-WARNINGS): 100MB-class assets load successfully, but with ~30s load times.
  • Gate 3 (PASSED): Optimized GLB pipeline via Docker-free trimesh + gltf-transform.
  • Gate 4 (NOT STARTED): 3 legacy cards rebuilt (Planned for W9).

3. System Architecture & Flow

The backend operates via a simple Next.js API integrated with an Express host for running locally.

Backend Data Flow

Project (Top level namespace with API Key) │ ├── MediaAsset (3D models, audio, etc.) │ └── sourceAssetId tracks conversion lineage (e.g. OBJ -> optimized GLB) │ ├── ImageTarget (The visual marker for AR tracking) │ └── boundExperienceId (1:1 with an ARExperience) │ └── ARExperience (The AR scene definition) ├── imageTargetId (Many:1 to ImageTarget) └── mediaAssetId (The asset to display)

Asset Upload & Viewer Flow

  1. Upload: POST /api/assets/upload -> Client uploads original source file (e.g., OBJ).
  2. Pipeline: Python scripts (trimesh + gltf-transform) convert OBJ to optimized GLB.
  3. Derived Asset: POST /api/assets/derived registers the optimized GLB with lineage back to the original.
  4. Viewer: src/components/ModelViewer.tsx loads the model using useGLTF or OBJLoader.

6. How to Run Locally

To run the application and backend on your local machine:

  • Start the backend: npm run dev:example-host (runs Express server on port 3001)
  • Start the frontend: npm run dev (starts Vite/React dev server)
  • Typecheck server: npm run typecheck:server
  • Database: Ensure PostgreSQL is running at localhost:5432/armarketer (configured via .env).

7. TASK-009 API Workflow — ARExperience CRUD & Binding

All endpoints below require the x-api-key header matching the project's API key. The backend runs on http://localhost:3001 via npm run dev:example-host.

Create an Experience

POST /api/experiences curl -s -X POST http://localhost:3001/api/experiences \ -H "Content-Type: application/json" \ -H "x-api-key: <PROJECT_API_KEY>" \ -d '{ "projectId": "<PROJECT_ID>", "name": "My AR Scene", "contentType": "MODEL_3D", "mediaAssetId": "<ASSET_ID>" }' # Returns 201 with the created ARExperience object. # Required: projectId, name, contentType. Returns 400 if any are missing. # Returns 422 if a constraint is violated (e.g. duplicate name).

List Experiences for a Project

GET /api/experiences?projectId=<PROJECT_ID> curl -s "http://localhost:3001/api/experiences?projectId=<PROJECT_ID>" \ -H "x-api-key: <PROJECT_API_KEY>" # Returns 200 with an array of ARExperience objects. # Returns 400 if projectId query param is missing.

Get a Single Experience

GET /api/experiences/:id curl -s http://localhost:3001/api/experiences/<EXPERIENCE_ID> \ -H "x-api-key: <PROJECT_API_KEY>" # Returns 200 with the ARExperience object. # Returns 404 if not found.

Update an Experience

PATCH /api/experiences/:id curl -s -X PATCH http://localhost:3001/api/experiences/<EXPERIENCE_ID> \ -H "Content-Type: application/json" \ -H "x-api-key: <PROJECT_API_KEY>" \ -d '{"name": "Updated Name", "imageTargetId": "<TARGET_ID>"}' # Returns 200 with updated object. # Returns 422 if imageTargetId does not belong to the same project.

Delete an Experience

DELETE /api/experiences/:id curl -s -X DELETE http://localhost:3001/api/experiences/<EXPERIENCE_ID> \ -H "x-api-key: <PROJECT_API_KEY>" # Returns 204 No Content on success. # Returns 404 if not found.

Bind an Experience to an ImageTarget

POST /api/targets/:id/bind/:experienceId curl -s -X POST \ "http://localhost:3001/api/targets/<TARGET_ID>/bind/<EXPERIENCE_ID>" \ -H "x-api-key: <PROJECT_API_KEY>" # Returns 200 with the updated ImageTarget (boundExperienceId set). # Pre-conditions: # - Experience and target must belong to the same project. # - experience.imageTargetId must already be set to this target's id. # Returns 422 if either condition is not met.

Unbind an Experience from an ImageTarget

DELETE /api/targets/:id/bind curl -s -X DELETE \ "http://localhost:3001/api/targets/<TARGET_ID>/bind" \ -H "x-api-key: <PROJECT_API_KEY>" # Returns 204 No Content. Sets target.boundExperienceId to null.

8. Key Risks & Known Limitations

  • Large Asset Loading: Loading 100MB+ models works, but can take ~30 seconds on mobile.
  • MindAR Version: Locked at 1.2.5. Do NOT upgrade without running the Gate 1 test protocol again.
  • Storage Provider: R2 credentials are for deployment. Local development defaults to LOCAL storage.

9. Troubleshooting

401 Unauthorized on API calls

The x-api-key header is missing or wrong. Retrieve the project's apiKey from the database: SELECT "apiKey" FROM "Project" WHERE id = '<id>';. Projects without an API key are open (no header needed).

422 on POST /api/targets/:id/bind/:experienceId

Two common causes: (1) the experience's imageTargetId is not set to the target you are binding to — PATCH the experience first; (2) the experience and target belong to different projects.

Backend fails to start

  • Check PostgreSQL is running: pg_isready -h localhost -p 5432
  • Verify .env has DATABASE_URL="postgresql://postgres:postgres@localhost:5432/armarketer"
  • Run npx prisma migrate deploy if migrations are pending.

TypeScript errors in server code

Run npm run typecheck:server. This runs prisma generate first, then tsc -p tsconfig.server.json --noEmit. If Prisma client is out of date, npx prisma generate alone is enough to fix phantom type errors.

Asset upload returns 413

The Express host accepts up to 500 MB for binary PUT requests. If you hit 413 on a JSON endpoint, the body exceeds the 1 MB JSON limit — check you are not base64-encoding a file into a JSON field.
